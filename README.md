# Quiz Schedule Bot (Астана)

Telegram-бот, который собирает расписание квиз-игр с разных сайтов
и Telegram-каналов и отдаёт его пользователю по командам `/today`, `/week`.

## Что уже готово и протестировано

- `models/event.py` — модель события + дедупликация по хэшу
- `utils/date_parser.py` — парсер дат на русском и казахском (протестирован
  на реальных строках из вашего файла расписания, см. `tests/test_date_parser.py`)
- `storage/` — SQLite через SQLAlchemy (async), сохранение с игнором дублей
  на уровне БД (`INSERT OR IGNORE`), протестировано в `tests/test_storage.py`
- `parsers/base.py` — базовый класс: падение одного источника не роняет остальные
- `bot/` — минимальный aiogram-бот с командами `/start`, `/today`, `/week`,
  плюс административная `/post_today` (см. ниже)
- `scheduler/jobs.py` — **парсинг по запросу, без фонового расписания.**
  Сайты не дёргаются по таймеру — `ParseCoordinator` запускает парсинг всех
  источников лениво, при первом обращении к боту (`/today`, `/week`,
  `/post_today`) после того, как предыдущие данные "протухли"
  (`PARSE_INTERVAL_MINUTES` — теперь это порог свежести кэша, а не интервал
  таймера). Если бот час простаивает без единого сообщения — ни один сайт
  за это время не трогается, никакой фоновой нагрузки на CPU/сеть.
  `asyncio.Lock` не даёт двум одновременным вызовам от разных пользователей
  запустить парсинг параллельно дважды — второй просто дождётся первого.
  Сам парсинг всё ещё ограничен по параллелизму (`MAX_CONCURRENT_PARSERS`,
  по умолчанию 4) — часть парсеров поднимает настоящий Chromium через
  Playwright, и без лимита на слабой машине они конкурируют за CPU/RAM и
  падают по таймауту (воспроизведено на практике при прогоне всех 15
  источников разом).

**Парсеры сайтов — 12 источников.** Action, Teztap и Whiz Quiz отключены:
их игры добавляются вручную (см. «Ручное добавление»). Instagram-страницы

Несколько важных находок по дороге, актуальных для любого нового парсера:

- **`utils/date_parser.py` подхватывал случайный год из названия квиза.**
  Если в заголовке было что-то вроде "Тусич под хиты 2003-2004" или
  "РУССКИЕ ХИТЫ 2000-х", `extract_date` мог принять "2003"/"2000" за год
  события. Почти во всех сайтах, где дата и название были в одной строке
  (Teztap, Smuzi, Mohito, Whiz Quiz), пришлось явно вырезать префикс с
  датой и отдавать в `extract_date`/`extract_time` только его, а не всю
  строку целиком.
- **`extract_time` не находил время, если оно впритык к кириллице без
  пробела** (`"20:00Стоимость"` у Peace Quiz) — `\b` не срабатывает, когда
  оба соседних символа Python считает "словесными". Починено в самой
  утилите (`(?<!\d)`/`(?!\d)` вместо `\b`) — исправление касается всех
  парсеров сразу, добавлен регрессионный тест.
- **Некоторые сайты обслуживают несколько городов с одного домена** —
  Chill Quiz без cookie `city_slug=astana` отдаёт вперемешку Алматы и
  Астану. Это стоит проверять отдельно для любого нового источника, а не
  доверять URL в духе `.../astana` — далеко не все сайты фильтруют по нему.
- **Локаль браузера имеет значение** — Detequiz без `locale="ru-RU"` в
  Playwright-контексте отдаёт англоязычную версию с датами вида
  "Sun 27 Sept" вместо "вс, 27 сент.".
- **Параллелизм Playwright-парсеров нужно ограничивать** — см. выше про
  `MAX_CONCURRENT_PARSERS`.
- **Сервер живёт по UTC, а квизы — по времени Астаны (UTC+5).** Везде, где
  коду нужно "сегодня" (`/today`, `/week`, удаление прошедших, разбор
  "Сегодня, 20:00" у QuizPlease, определение года при парсинге дат), это
  раньше считалось через голый `date.today()` — то есть по часовому поясу
  сервера. В окне 00:00-04:59 по Астане это ещё "вчера" по UTC, и бот
  показывал устаревшее на день расписание (воспроизведено на практике —
  запрос в 00:10 по Астане 1 октября вернул данные за 30 сентября).
  Починено через `utils/clock.py::today_astana()` (часовой пояс
  `Asia/Almaty`, тот же что у Астаны) — используется везде вместо
  `date.today()`. На Windows для `zoneinfo` нужен пакет `tzdata` (добавлен
  в `requirements.txt`) — на Linux-серверах обычно есть системная база
  часовых поясов, но пакет не мешает и подстраховывает.

## Ручное добавление квизов (для Instagram-источников)

Автоматический парсинг Instagram сознательно не делается (см. ниже, почему) —
вместо этого админ может добавить квиз руками через пошаговый диалог с ботом.
Такие события хранятся в той же таблице, что и спарсенные — попадают в
`/today`/`/week` и точно так же автоматически удаляются после даты события.

- Кнопка **➕ Добавить квиз** (или команда `/add_event`, видна только админу) —
  бот по шагам спрашивает источник, дату, время, название, место, затем
  показывает превью с кнопками "✅ Сохранить"/"❌ Отмена"
- Кнопка **📋 Мои квизы** (`/my_events`) — список вручную добавленных
  предстоящих квизов, у каждого кнопка "🗑 Удалить" — на случай опечатки
  или отмены игры
- Всё управление — кнопками постоянной клавиатуры под полем ввода
  (`bot/keyboards.py`), набирать команды вручную не обязательно

Код — `bot/handlers/admin.py` (`AddEventStates`), поле `is_manual` в
`storage/db.py`/`models/event.py` отличает такие события от спарсенных.

## Постинг опроса с расписанием в канал (`/post_today`)

Админская команда: строит превью нативного опроса Telegram (галочки,
анонимный, множественный выбор) со всеми квизами на сегодня и публикует
его в канал по нажатию инлайн-кнопки — сама команда ничего не постит,
только показывает превью. Вопрос опроса — "2 октября, пятница - сегодня я
иду…", последний вариант всегда "сегодня давайте без меня 😎" (поэтому
квизов в одном опросе максимум 9 при лимите Telegram в 10 вариантов — если
больше, делает несколько опросов подряд, каждый со своей кнопкой). Даже при
одном квизе опрос возможен: квиз + "без меня" = 2 варианта.

**Настройка** (без неё команда отвечает, что не настроена):
1. В `.env` — `ADMIN_USER_ID` (числовые Telegram ID админов через запятую,
   узнать у `@userinfobot`) и `CHANNEL_ID` (юзернейм `@channel` или числовой
   ID канала)
2. Добавить бота в канал администратором с правом публиковать сообщения
3. Написать боту `/post_today` в личку (сработает для любого ID из `ADMIN_USER_ID`)

Админские права (публикация опроса, ручное добавление квизов) одинаковы для
всех перечисленных ID — отдельных ролей ("только постить" / "только
добавлять") нет.

Код — `bot/handlers/admin.py`.

## Что НЕ готово и требует вашего участия

**Instagram/Telegram-каналы без сайта** (Talqyla, Alibi, Sainttwins, Day off
quiz, Blackbox, Svoy, Beast case, Quizmania, Мозгобаттл) — автоматический
парсинг не делается (Instagram активно банит автоматизацию, Telegram-каналы
требуют личный аккаунт через `Telethon`/`Pyrogram` и нестабильный парсинг
текста постов). Вместо этого — ручное добавление через диалог с ботом,
см. раздел выше.

**Instagram** — сознательно отложен, как договорились.

Если появится новый сайт-источник — `_static_template.py` (статика,
образец — `playquiz.py`/`einstein.py`) или скопировать любой из
Playwright-парсеров (`chill.py`, `wow.py` — хорошие примеры) под
JS-сайты, дальше добавить в `build_parsers()` в `bot/main.py`.

## Хостинг (бесплатный)

Бот разделён на две части:

- **Парсинг — GitHub Actions** (`.github/workflows/scrape.yml`). Каждые 3 часа
  GitHub запускает `python -m scheduler.scrape` в своей машине (там есть
  Chromium) и пишет результат в облачную базу. Запустить вручную: вкладка
  Actions → «Обновление расписания» → Run workflow.
- **База — Neon** (бесплатный Postgres). Там и спарсенное расписание, и ручные
  квизы. Строка подключения — секрет `DATABASE_URL` в GitHub (Settings →
  Secrets and variables → Actions) и переменная окружения на Render.
- **Бот — Render** (`render.yaml`), режим вебхука, без парсинга. Бесплатный
  Render засыпает через ~15 минут простоя: первый ответ после паузы приходит
  с задержкой до минуты.

- **Ежедневный опрос в канал — GitHub Actions** (`.github/workflows/daily_poll.yml`).
  Каждый день в 12:00 по Астане (07:00 UTC, GitHub может опоздать на 5–30
  минут) публикует в `CHANNEL_ID` опрос «сегодня я иду...» без превью. Нужны
  секреты `BOT_TOKEN` и `CHANNEL_ID` в GitHub. Время меняется в строке `cron`.

Локально (`python -m bot.main` без `WEBHOOK_BASE_URL`) бот работает как раньше:
поллинг и парсинг по нажатию. При запуске он снимает вебхук — если бот в это
время развёрнут на Render, тот перестанет получать сообщения до перезапуска.

Перенос событий и ручных квизов из локального файла в облако:
`python -m scripts.copy_to_cloud` (берёт `DATABASE_URL` из `.env`).

## Запуск

```bash
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium     # один раз, для Playwright-парсеров

cp .env.example .env
# впишите BOT_TOKEN, полученный у @BotFather

python -m bot.main
```
